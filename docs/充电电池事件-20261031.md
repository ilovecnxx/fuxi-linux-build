# 2026-10-31 充电/电池事件记录

## 结论（一句话）

手机在 Linux 下接**电脑 USB 口**（SDP，只有 5V/500mA）跑 Denial 源码构建（8 路 clang 占满 CPU，
整机消耗 ~2A），把电池耗到 1% 后关机。**不是神秘故障**：电脑 USB 供不上 2A 负载；PD 快充本身
仍未在 Linux 下验证（一直是待办）。

## 结论与后续修复点

1. **电脑 USB 只有 500mA**，只能慢充；要充电必须插 **67W/PD 充电器**（用户已插，Android 识别为 AC）。
2. **第三方系统快充现状（实测）**：LineageOS 24 下 UCSI-PMIC-GLINK 的 PD 3.0 已协商成功、
   充电器广播 20V/3.25A（65W PD+PPS），但**实际 VBUS 停在 5V/1.6A（8W）**——手机没有请求
   升压到 20V。这说明 67W MiPPS / 高电压 PD 的升压由小米原厂充电驱动主动选择；第三方系统
   默认走 ADSP 固件的保守档（5V/1.6A）。
3. **Linux 侧**：`qcom_battmgr` 驱动只读上报，无写控制；PD 协商由 ADSP `charger_pd` 固件完成。
   能否升压需回 Linux 实测（同一充电器），不达标再评估 UCSI-PMIC-GLINK（当前 Linux 内核
   `CONFIG_UCSI_PMIC_GLINK` 未启用）/固件协议路线。
4. **待办**：手机在 Android 充到 50% 左右 → 回 Linux → 插 67W 头实测 `qcom-battmgr-usb`
   的 VOLTAGE_NOW/CURRENT_MAX/USB_TYPE；若仍是 5V/500mA~1.6A，启动 UCSI-PMIC-GLINK 路线调研。
