# 小米 13（fuxi）双系统：Android + 主线 Linux（Ubuntu）

更新：2026-10-27。快照：`images/recovery-linux.img`（最后设备验证镜像 abl-fuxi-wifi1，sha256 见根目录 `SHA256SUMS`）。

## 现状

| | Android | 主线 Linux |
|---|---|---|
| 系统 | LineageOS 24.0（槽位 b） | 主线内核 7.3 + Ubuntu 26.10 |
| 引导 | ABL → `boot_b` 等原厂分区 | ABL → **`recovery_b`**（主线内核镜像 8,691,712 B；候选镜像 9,748,480–10,485,760 B） |
| 根文件系统 | `super` + `userdata`（362 GB，已用 3.4 GB） | `linux` 分区 sda33（100 GB，已用 1.2 GB） |
| 开机到可用 | 约 20 秒 | 实测重启到 SSH 可用约 16 s（更早记录：内核 8.7–8.9 s + 用户空间 2.0–2.5 s） |

## 怎么切换（都不需要电脑）

- **进 Linux**
  - 关机状态：按住 **音量上 + 电源** 开机；
  - 在 Android 里：电源菜单 → 重启 → **Recovery**（LineageOS 需在 开发者选项 里打开"高级重启"）；
  - 电脑上：`adb reboot recovery`。
- **回 Android**：在 Linux 里正常重启（`reboot` / `systemctl reboot`）。
- **进 fastboot**：Linux 里 `systemctl reboot --reboot-argument=bootloader`，或按住 音量下 + 电源。

## Linux 访问方式

- 屏幕：simpledrm + fbcon（tty1 登录界面，16×32 字体）。
- 按键：电源（`pmic_pwrkey`）、音量下（`pmic_resin`）、音量上（`gpio-keys`，PM8550 GPIO6）。电源键暂设为 ignore
  （`/etc/systemd/logind.conf.d/10-fuxi-powerkey.conf`）。
- 触摸：ST FTM5（SPI，spi4），新写的主线驱动 `drivers/input/touchscreen/st-ftm5.c`（364 行，checkpatch 0 警告）。
  坐标 1/10 像素（0..10799 × 0..23999），方向与屏幕一致，多点。还没有图形界面可用它。
- USB 网络：手机 `10.42.0.2`，电脑 NetworkManager 共享连接 `fuxi-usb`（`10.42.0.1`，自动 NAT）。
- SSH：`scripts/fuxi-ssh.sh`（密钥 `work/ssh/fuxi_root`）。
- USB 串口：`/dev/fuxi-acm`，root 自动登录（`fuxi-serial-shell.service`）。

## 启动链

```
XBL → 高通 UEFI → ABL（槽位 b）
  正常开机   → boot_b … → Android
  recovery  → recovery_b：boot.img v1，kernel = Image.gz + 厂商 fuxi.dtb（诱饵）
              → 主线内核（CONFIG_FUXI_FORCE_BUILTIN_DTB：忽略 ABL 的 DTB，用内建主线 DTB；
                 cmdline 来自 DTS /chosen/bootargs）
              → initramfs：USB 串口就绪后 8 秒内主机没 `touch /tmp/stay` 就
                 switch_root 进 sda33 上的 Ubuntu（systemd）
```

ABL 必须拿到厂商 DTB：它会把 `dtbo` 分区的 overlay 叠到 DTB 上，叠到主线 DTB 会卡死（用"立即 PSCI 复位"的
最小桩内核验证过：附主线 DTB 卡住，附厂商 DTB 19 秒回 Android）。

## 构建与更新 Linux 内核

```
scripts/fuxi-build-abl.sh <名字>      # → work/kbuild/abl-fuxi-<名字>.img
# 推荐（不用 fastboot）：在 Android 里写 recovery_b → 重启进 Linux → ssh 跑命令 → 回 Android
scripts/fuxi-test-recovery.sh work/kbuild/abl-fuxi-<名字>.img '<ssh 命令>' …
#   FUXI_STAY=1：留在 initramfs 串口 shell 执行命令；FUXI_KEEP=1：测完不回 Android
# 测试镜像起不来：长按电源 20 秒即回 Android。
```

## 主线源码树的本地改动（2026-10-27 v0.2.0）

完整差分与新增文件见仓库 `source/`（`kernel.diff` + `linux-untracked/`），构建信息见 `source/BUILD-INFO.md`。

- 受跟踪文件改动 **13 个、+165/−7**：`CONFIG_FUXI_FORCE_BUILTIN_DTB`（Kconfig + setup.c + Makefile）、
  `fuxi.nosync` 诊断（drivers/base/core.c）、面板驱动 `panel-xiaomi-fuxi`、触摸 `st-ftm5`、
  相机电源 `fuxi-camera-power`、UFS 关机复位修复（ufs-qcom）、`qcom_battmgr` 属性、音频 `sc8280xp`。
- 新增 **23 个文件**：主/变体 DTS 与 dtsi（`-disp/-usbc/-audio/-audio2/-camera/-modem/-sleep/-desk/-full`）、
  `fuxi_dtb.S`、`fuxi_early.c`、`fuxi_font.h`、`panel-xiaomi-fuxi.c`、`st-ftm5.c`、`fuxi-camera-power.c`。
- 变体配置由 `scripts/fuxi-build-abl.sh` 构建时临时打开、结束后恢复主配置：
  `FUXI_DTB=sm8550-xiaomi-fuxi-full scripts/fuxi-build-abl.sh full3`；调频温控加 `FUXI_PM=1`。
- 显示说明：simpledrm 路径下 DTS 里 `&mdss` 启用但不编 DRM_MSM、去掉 `iommus`，作为等不到驱动的消费者
  让 mmss_noc/gem_noc/MMCX 的 sync_state 挂起、保留 bootloader 投票（不再需要 `fuxi.nosync`）；
  `-disp/-desk/-full` 变体才临时打开 DRM_MSM/面板/GPU，两者不要混用同一镜像。

## 恢复原厂

- recovery：用**你自己的**原厂 `recovery_b` 备份写回 `recovery_b`（备份不随仓库发布）；
- 槽位 a：`boot_a` 已写回原厂（sha256 `c02adcce…`）。`fastboot set_active a` 曾把 50 多个分区
  （abl/tz/hyp/aop/modem/uefi…）的 active 位一起切换；不要自己改 GPT 槽位属性。

## 已知坑

- 内核 cmdline **不要加 `console=ttyGS0`**：/dev/console 变成 USB 串口，主机没读时写满阻塞，
  启动卡几分钟、关机永远卡住。
- ABL 一次失败启动后，同一 fastboot 会话里拒绝后续镜像：先 `fastboot reboot bootloader`。
- 不要对半初始化的 `ath12k` 做 unbind/rebind：会卡死整机（WiFi 固件要在根文件系统就绪后由 `fuxi-firmware-devices` 启动）。
- 电脑 USB：`usb1-port6` 过流 399 次；出现 `error -71`、只能 full-speed 时是线材/接口信号问题，换线。
  `scripts/udev/52-fuxi-usb-port-power.rules` 允许脚本"软件拔插"。
- UFS HS-G5 补丁暂缓（`source/patches/ufs-qcom-sm8550-g5.patch`）：在 G5 下 `reboot -f` 曾进 EDL。
- **重启偶尔进 EDL（UFS 关机路径）**：主线 `ufs-qcom` 关机时不释放 UFS 复位线，启动 ROM 读不到引导分区。
  `wifi3` 起的镜像已加 `.shutdown` 释放复位线，但**发布镜像（wifi1，07:24）不含该修复**，尚未实机验证；
  日常重启若进 EDL，长按电源 20 秒或等约 85 秒会自行退出。
